## หลักฐานก่อนเปิด PR

- ไฟล์เทส: `<TEST_FILE>`
- `feat` / `fix`: เทสของพฤติกรรมนั้นแดงเพราะ assertion ยังไม่จริง แล้วเขียวก่อนเปิด PR
- `fix` ที่ผู้ใช้เห็นจอ: ขั้นตอนที่ทำให้บั๊กเกิด / ขั้นตอนเดิมหลังแก้

## เปิด PR เมื่อ

- ผลคำสั่งในหัว **พิสูจน์** ของ card
- `<TEST_CMD>` ของป้ายข้อ ขอบเขตที่เกี่ยวกับไฟล์ที่เปลี่ยน (`feat` / `fix` ห้ามข้าม ถ้าตารางว่างใช้คำสั่งในหัว **ตรวจผ่านเมื่อ** ชนิดอื่นข้ามได้แล้วเขียนว่าไม่มีชุดเทส)
- `<TYPECHECK_CMD>` / `<LINT_CMD>` ถ้าช่องไม่ว่างและแตะไฟล์ที่ครอบ
- เนื้อ PR มี diff, ผลเทส, และหลักฐานบนพื้นผิวถ้าเป็น `fix` ที่ผู้ใช้เห็นจอ
