# Workflow — หยิบงานจาก backlog

Kit `repo-workflow` เวอร์ชัน **9** — ตอน copy ให้คงบรรทัดนี้ แล้วอย่าลบเลขเวอร์ชัน

ใช้กับ [backlog/README.md](backlog/README.md) · บทบาท skill อยู่ที่ [skills.md](skills.md) · โครง card/plan ใช้ไฟล์ที่ copy จาก kit อย่าลอกจากที่นี่

คนทำสองอย่าง: **เขียน card** และ **เปลี่ยนคำบนบรรทัด backlog** ที่เหลือเป็นงานของเอเจนต์

## ตั้งค่าโปรเจกต์

เติมก่อนใช้ ค่าในตารางนี้เป็นของ **repo นี้** ไม่ใช่ของ kit

`<STACK_LOCK>` ต้องชี้ไปข้อความที่มีอย่างน้อย: ภาษา · เฟรมเวิร์ก · คำสั่งเทส/type/lint ต่อป้าย (หรือชี้กลับมาที่ตารางนี้) · ของที่ห้ามใช้ในโปรเจกต์นี้

อ่าน `<STACK_LOCK>` ก่อนเปิด skill ที่พูดถึงภาษา เฟรมเวิร์ก ไลบรารี หรือโฮสต์คลาวด์

| Placeholder | ค่าใน repo นี้ |
|---|---|
| `<TEST_CMD>` | ต่อป้าย เช่น `web: npm test` · หลายป้ายเขียนในช่องนี้ · เว้นว่างได้ถ้าไม่มีชุดเทส |
| `<TYPECHECK_CMD>` | ต่อป้าย · เว้นว่างได้ |
| `<LINT_CMD>` | ต่อป้าย · เว้นว่างได้ |
| `<BROWSER_TOOL>` | (เว้นว่างถ้าไม่มี UI ให้ไล่) |
| `<STACK_LOCK>` | |
| `<OTHER_REPO>` | ป้ายทั้งหมด คั่นด้วย comma · อย่างน้อยชื่อโฟลเดอร์แอปหนึ่งอัน · ห้ามเว้นว่าง |

คิวอยู่ที่ `work/` ใน repo นี้ สถานะที่เอเจนต์เชื่อมีแค่คำบนบรรทัด backlog อย่าอ่านปุ่ม review ของโฮสต์ อย่าคิวใน vault หรือโฟลเดอร์ spec

- **backlog** (`work/backlog/README.md`) = คิว ที่ปิดข้อคือที่นี่
- **card** (`work/backlog/<id>.md`) = ข้อตกลงที่คนเขียน (ทำ / ไม่ทำ / ตรวจผ่านเมื่อ / ชนิด / ทางที่เลือกแล้ว)
- **plan** (`work/plans/<id>.md`) = โน้ตลงมือของเอเจนต์ คนไม่รับแผนก่อนเปิดของให้ review
- **skills** (`work/skills.md`) = เปิดได้สี่จุด ไม่เกินสองใบต่อจุด ไม่แทนการเปลี่ยนคำบนบรรทัด backlog

```text
คนเขียน card
    → เอเจนต์หยิบ
        เจตนายังไม่ปิด → เขียน ถาม ที่ card และบรรทัด backlog → ไม่เปิดของให้ review → กลับไปที่คน
        เจตนาปิดแล้ว → ลงมือบน branch → เก็บผลเทสและหลักฐานบนพื้นผิว
            ย้อนกลับไม่ได้ หรือครบ 3 รอบแล้วยังไม่ผ่าน → เขียน ถาม ที่ card และบรรทัด backlog → ไม่ขอ review
            ผ่าน → เปิดของให้คน review แล้วตั้งบรรทัดเป็น รอรีวิว
                คนเทียบ diff กับตรวจผ่านเมื่อ และหลักฐานครบ
                    ครบแล้วรับ → ติ๊ก merge
                    ไม่ครบหรือยังไม่ตรง → เปลี่ยนบรรทัดเป็น ส่งกลับ
                    ไม่เอา → ติ๊ก ปิด
```

## กติกา

- หนึ่งข้อที่กำลังทำ มีได้ข้อเดียว ก่อนหยิบข้อใหม่ให้อ่านคำบนบรรทัด backlog ตามขั้น 2 ไม่ดูปุ่มของโฮสต์
- ข้อที่บรรทัดเป็น `ส่งกลับ:` ทำต่อของเดิม ไม่เปิดของใหม่ให้ review พอหลักฐานผ่านให้เปลี่ยนบรรทัดเป็น `รอรีวิว:` แล้วหยุด
- เจตนาไม่ปิด งานย้อนกลับไม่ได้ หรือครบ 3 รอบแล้วยังไม่ผ่านหลักฐาน → เขียน `ถาม:` ทั้งท้าย card และท้ายบรรทัด backlog แล้วหยุด ห้ามเปิดของให้ review
- เปิดของให้ review ได้เมื่อหลักฐานครบ เทสที่เกี่ยวข้องเขียว และ diff อยู่ในหัว **ทำ** / **ไม่ทำ** ของ card
- คนติ๊ก `merge:` ได้เมื่อเทียบ diff กับหัว **ตรวจผ่านเมื่อ** แล้ว และหลักฐานครบ หลักฐานไม่ครบให้เปลี่ยนบรรทัดเป็น `ส่งกลับ:` ห้ามติ๊กเพราะคำอธิบายดูเรียบ
- เอเจนต์ห้ามติ๊ก `merge:` หรือ `ปิด:` และห้าม merge สาขาหลัก
- ยังไม่ push สาขาหลัก จนกว่าคนจะติ๊ก `merge:` เอง
- อย่าใส่ trailer ของโมเดลใน commit

### เจตนาปิดแล้ว

card มีชนิดเดียว ป้ายเดียว ทางเดียว และหัว **ทำ** **ไม่ทำ** **ตรวจผ่านเมื่อ** อ่านแล้วลงมือได้โดยไม่ต้องเลือกแทนคน

ยังไม่ปิดเมื่อ: ขอบเขตคลุมเครือ · สองทางที่ผลไม่เท่ากัน · จะลบของที่อาจยังมีคนใช้โดย card ยังไม่เลือก · จะเปลี่ยนสัญญาที่คนอื่นเรียกโดย card ยังไม่เลือก · หลายป้ายในข้อเดียว

### งานที่ย้อนกลับไม่ได้

หยุด เขียน `ถาม:` ที่ card และบรรทัด backlog ห้ามลงมือต่อเมื่อจะ: ลบข้อมูล production · force-push · ส่งข้อความหรือของออกนอก repo · merge สาขาหลัก

push branch ของข้อเพื่อเปิดของให้ review ทำได้ การติ๊ก `merge:` เป็นของคน

### เกณฑ์ 3 รอบ

หนึ่งรอบ = พยายามทั้งชุดจนจบครั้งหนึ่ง ไม่ใช่ทุกคำสั่งเทส หลักฐานคือเทสที่เกี่ยวข้องเขียว และถ้าเป็น `fix` ที่ผู้ใช้เห็นจอ ขั้นตอนเดิมบนพื้นผิวเดิมไม่เกิดบั๊ก

เริ่มที่ `รอบหลักฐาน` = 1 ใน plan พยายามทั้งชุดแล้วยังไม่ผ่าน ให้ดูค่าปัจจุบันก่อน ถ้าน้อยกว่า 3 ให้บวก 1 แล้วพยายามใหม่ ถ้าค่าเป็น 3 อยู่แล้วและยังไม่ผ่าน → `ถาม:` ที่ card และที่บรรทัด backlog ห้ามขอ review เทสแดงที่ตั้งใจก่อนลงมือไม่นับเป็นรอบที่ล้ม
คนเปลี่ยนบรรทัดจาก `รอรีวิว:` เป็น `ส่งกลับ:` คือคำขอใหม่ ครั้งแรกที่เอเจนต์เห็นให้ตั้ง `รอบหลักฐาน` เป็น 1 และตั้ง `สถานะรอบ` ใน plan เป็น `ส่งกลับ` ถ้า plan เป็น `ส่งกลับ` อยู่แล้ว ห้ามรีเซ็ตซ้ำ
หลักฐานผ่านขณะบรรทัดเป็น `ส่งกลับ:` ให้เปลี่ยนบรรทัดเป็น `รอรีวิว:` ตั้ง `สถานะรอบ` เป็น `รอรีวิว` commit ที่ `work/` แล้วหยุด งานที่หลักฐานยังไม่ผ่านห้ามเปลี่ยนเป็น `รอรีวิว:`

นับรอบจากช่อง `รอบหลักฐาน` ใน plan เท่านั้น

### ถาม

วางท้าย card และต่อท้ายบรรทัด backlog ด้วย `ถาม:` โดยข้อยังเป็น `- [ ]` แล้ว commit บรรทัดนั้นที่ `work/` แล้วหยุด ห้ามเปิดของให้ review

```markdown
ถาม: <หนึ่งคำถาม>
ทำไมถึงไปต่อไม่ได้: …
ทางที่เห็น: A … / B …
```

คนตอบด้วยการล้างหัว **ถาม** ใน card และแก้ card จนเจตนาปิด ไม่ต้องแก้บรรทัด backlog
เอเจนต์เห็นหัว **ถาม** ว่างและเจตนาปิดแล้ว จึงลบ `ถาม:` ออกจากบรรทัด backlog commit ที่ `work/` แล้วหยิบข้อนั้นต่อได้

## ชนิดตั๋ว

ใส่ใน card หนึ่งค่า จากชุดที่ Conventional Commits อนุญาตให้เพิ่ม และที่ `@commitlint/config-conventional` ใช้

| ชนิด | ความหมาย | หลักฐานก่อนเปิดของให้ review |
|---|---|---|
| `feat` | พฤติกรรมหรือ interface ใหม่ | เทสของพฤติกรรมนั้นเขียว ด้วย `<TEST_CMD>` หรือคำสั่งที่หัว **ตรวจผ่านเมื่อ** เขียนไว้ |
| `fix` | บั๊กที่พฤติกรรมพัง | เทสของพฤติกรรมนั้นเขียว ด้วย `<TEST_CMD>` หรือคำสั่งที่หัว **ตรวจผ่านเมื่อ** เขียนไว้ |
| `docs` | เอกสารอย่างเดียว | ไม่แตะโค้ดผลิต |
| `style` | จัดรูปแบบ ความหมายของโค้ดไม่เปลี่ยน | ชุดเดิมผ่าน |
| `refactor` | ไม่แก้บั๊กและไม่เพิ่มพฤติกรรม รวมการลบของที่ไม่มีคนใช้ | ชุดเดิมผ่าน |
| `perf` | ทำให้เร็วขึ้น พฤติกรรมผู้ใช้เท่าเดิม | ชุดเดิมผ่าน |
| `test` | เพิ่มหรือแก้เทส | เทสที่เพิ่มเขียว โดยไม่เปลี่ยนพฤติกรรมผลิตเพื่อให้ผ่าน |
| `build` | ระบบ build หรือ dependency | ชุดเดิมผ่าน |
| `ci` | สคริปต์ CI | ชุดเดิมผ่าน |
| `chore` | งานอื่นที่ไม่ได้เปลี่ยนซอร์สหรือเทส | ชุดเดิมผ่าน |
| `revert` | ย้อน commit เดิม | หลังย้อน ชุดเดิมผ่าน |

`fix` ที่ผู้ใช้เห็นจอ: ทำให้บั๊กเกิดบนพื้นผิวเดิมก่อนลงมือ แล้วทำขั้นตอนเดิมหลังแก้จนไม่เกิด ใส่ขั้นตอนและผลไว้ในของที่เปิดให้ review เทสเขียวแต่พื้นผิวยังเป็นบั๊ก = ยังเปิดให้ review ไม่ได้ ห้ามเปิดโดยเขียนว่าตรวจพื้นผิวไม่ได้
`<BROWSER_TOOL>` ว่าง และหัว **ตรวจผ่านเมื่อ** ไม่ได้เขียนวิธีตรวจพื้นผิว = เจตนายังไม่ปิด เขียน `ถาม:` ขอวิธีตรวจ

`<TEST_CMD>` ว่าง และ card ของ `feat` หรือ `fix` ไม่ได้เขียนคำสั่งเทสไว้ในหัว **ตรวจผ่านเมื่อ** = เจตนายังไม่ปิด เขียน `ถาม:` ขอคำสั่งเทส ห้ามเปิดของให้ review โดยบอกว่าไม่มีชุดเทส
ชนิดอื่นเมื่อ `<TEST_CMD>` ว่าง เขียนในของที่เปิดให้ review ว่าไม่มีชุดเทสได้

ชื่อเทสตาม scenario / พฤติกรรม — ห้ามตั้งชื่อเทสตามรหัสการ์ด

### มาตรฐาน commit

```text
<ชนิด>(<id>): <สรุป>
```

- `<ชนิด>` ตรงชนิดของ card
- `<id>` ตรงชื่อไฟล์ card
- `<สรุป>` ภาษาอังกฤษ รูปคำสั่ง ปัจจุบัน ไม่ขึ้นต้นด้วยตัวใหญ่ ไม่มีจุดท้าย
- บรรทัดว่างแล้วตามด้วยเหตุผลหนึ่งประโยค ยกเว้นชนิด `docs`
- หนึ่ง commit หนึ่งชนิด ถ้าเข้าสองชนิดให้แยก commit
- งานนอกคิวไม่มี `<id>` ถ้าจะอยู่ในลูปให้มี card ก่อน
- อย่าใส่ trailer ของโมเดลใน commit

## 1. คนเขียน card

คนเขียน `work/backlog/<id>.md` ตามโครง card ของ kit ก่อนเอเจนต์หยิบ

ต้องมี: ชนิด · ป้ายเดียว · ทำ · ไม่ทำ · ตรวจผ่านเมื่อ · ทางที่เลือกแล้วถ้าเคยมีสองทาง

การลบของที่อาจยังมีคนใช้ และการเปลี่ยนสัญญาที่คนอื่นเรียก ต้องเป็นทางที่ card เลือกไว้แล้ว

---

## 2. เอเจนต์หยิบ

1. เปิด [backlog/README.md](backlog/README.md)
2. ใช้เงื่อนไขแรกที่ตรง ห้ามใช้พร้อมกัน
   - มี `- [ ]` ที่บรรทัดเป็น `ส่งกลับ:` และ `สถานะรอบ` ใน plan ยังไม่ใช่ `ส่งกลับ` → ตั้ง `รอบหลักฐาน` เป็น 1 ตั้ง `สถานะรอบ` เป็น `ส่งกลับ` commit ที่ `work/` แล้วทำข้อนี้ต่อ ห้ามเปิดของใหม่ให้ review ห้ามหยิบข้ออื่น
   - มี `- [ ]` ที่บรรทัดเป็น `ส่งกลับ:` และ `สถานะรอบ` เป็น `ส่งกลับ` อยู่แล้ว → ทำต่อโดยไม่รีเซ็ตรอบ ห้ามหยิบข้ออื่น
   - มี `- [ ]` ที่บรรทัดเป็น `รอรีวิว:` → หยุดรอคน ห้ามลงมือ ห้ามหยิบข้ออื่น คนจะเปลี่ยนคำบนบรรทัดเอง
3. ทุกบรรทัดที่ยัง `- [ ]` และมี `ถาม:` ให้อ่าน card
   - หัว **ถาม** ว่าง และเจตนาปิดแล้ว → ลบ `ถาม:` ออกจากบรรทัด backlog แล้ว commit ที่ `work/`
   - หัว **ถาม** ยังมีคำถาม → หยุด ห้ามหยิบข้ออื่น
4. ขั้น 2 หรือ 3 สั่งให้หยุดหรือทำต่อข้อเดิมแล้ว จบขั้นหยิบ
5. นอกนั้นหยิบข้อ `- [ ]` ที่ไม่มี `ถาม:` `รอรีวิว:` หรือ `ส่งกลับ:` และมีไฟล์ card ตามลำดับหัวข้อ **ทำก่อน** แล้ว **งานหลัก** แล้ว **เก็บเล็ก** บรรทัดที่เป็นหัวของข้อย่อยไม่ถูกหยิบ เมื่อข้อย่อยครบให้เขียนว่าครบที่บรรทัดหัว ตาราง P0–P4 ไม่ใช่คิวที่สอง
6. อ่าน card เจตนายังไม่ปิด → เขียน **ถาม** ท้าย card และต่อท้ายบรรทัด backlog commit ที่ `work/` แล้วหยุด ห้ามเปิดของให้ review
7. เจตนาปิดแล้ว → ไปลงมือ

ของที่ card ขอไม่มีในโค้ดแล้ว ให้เขียน `ถาม:` ว่าจะปิดข้อนี้ไหม ทั้งที่ card และบรรทัด backlog แล้ว commit ที่ `work/` ห้ามเปิดของให้ review และห้ามติ๊กเอง

## 3. เอเจนต์ลงมือบน branch

branch แยกจากสาขาหลัก plan อยู่ที่ `work/plans/<id>.md` คนไม่ต้องรับแผนก่อนเปิดของให้ review

- `feat` / `fix` — เขียนเทสของพฤติกรรมนั้นให้แดงเพราะ assertion ยังไม่จริง แล้วทำให้เขียว ห้ามเปิดของให้ review ตอนเทสยังแดง
- `test` — เทสที่เพิ่มเขียว โดยไม่เปลี่ยนพฤติกรรมผลิตเพื่อให้ผ่าน
- `fix` ที่ผู้ใช้เห็นจอ — บันทึกขั้นตอนที่ทำให้บั๊กเกิด แล้วขั้นตอนเดิมหลังแก้ต้องไม่เกิด
- ไฟล์นอก **ไฟล์ที่แตะได้** ใน plan ห้ามแก้
- งานที่ย้อนกลับไม่ได้ → **ถาม** ที่ card และบรรทัด backlog commit ที่ `work/` แล้วหยุด
- หลักฐานไม่ผ่านทั้งชุด → ทำตามหัว **เกณฑ์ 3 รอบ** ดูค่าปัจจุบันก่อน แล้วยังไม่ถึง 3 จึงบวก ค่าเป็น 3 อยู่แล้วและยังไม่ผ่าน → **ถาม** ที่ card และบรรทัด backlog commit ที่ `work/` แล้วหยุด

ก่อนเปิดของให้ review รันของป้ายข้อนั้น:

- `<TEST_CMD>` ในขอบเขตไฟล์ที่เปลี่ยน — ว่างได้เฉพาะชนิดที่ไม่ใช่ `feat` หรือ `fix` แล้วเขียนในของที่เปิดให้ review ว่าไม่มีชุดเทส
- `<TYPECHECK_CMD>` ถ้าแตะไฟล์ที่ type ครอบ และช่องนี้ไม่ว่าง
- `<LINT_CMD>` เช่นกัน
- แตะ UI และ `<BROWSER_TOOL>` ไม่ว่าง — ไล่เส้นที่เปลี่ยน รวมหน้าอื่นที่อ่าน state เดียวกัน และ empty / error / ตัวแปร route / ขนาดจอ ถ้าแตะ
- `<BROWSER_TOOL>` ว่าง และไม่ใช่ `fix` ที่ผู้ใช้เห็นจอ — ใส่ในของที่เปิดให้ review ว่าตรวจพื้นผิวอะไรไม่ได้

---

## 4. เอเจนต์เปิดของให้ review

เปิดของให้คน review ในแบบที่ repo นี้ใช้อยู่แล้วเมื่อหลักฐานผ่าน ถ้า repo ใช้ PR ให้เปิด PR ใบเดิมถ้ามีอยู่แล้ว ห้ามเปิดใบใหม่ของข้อเดียวกัน เนื้อที่คนดูต้องมี:

- สรุป diff ว่าตรงหัว **ทำ** และไม่ล้ำหัว **ไม่ทำ**
- ผล `<TEST_CMD>` / `<TYPECHECK_CMD>` / `<LINT_CMD>` ที่รัน
- `fix` ที่ผู้ใช้เห็นจอ: ขั้นตอนบนพื้นผิวเดิมก่อนแก้และหลังแก้

หลักฐานไม่ครบ ห้ามเปิด และห้ามขอ review

จากนั้นแก้ [backlog/README.md](backlog/README.md):

- ข้อยังเป็น `- [ ]`
- ต่อท้าย `รอรีวิว:` พร้อมที่อยู่ของของที่เปิดให้ดู
- ตั้ง `สถานะรอบ` ใน plan เป็น `รอรีวิว`
- ห้ามเปลี่ยนเป็น `- [x]`

อย่าหยิบข้อถัดไป

commit โค้ดของข้อ แล้ว commit บรรทัด backlog กับ plan ที่ `work/` คนละ commit ถ้าแยกกันได้

## 5. คนเปลี่ยนคำบนบรรทัด

คนเทียบ diff กับหัว **ตรวจผ่านเมื่อ** ของ card แล้วตรวจว่าหลักฐานครบ การตัดสินอยู่ที่คำบนบรรทัด backlog

- ครบ และตรง card → เปลี่ยนบรรทัดเป็น `- [x]` ต่อท้าย `merge:` แล้ว merge ของที่เปิดไว้ถ้า repo นี้มีขั้นนั้น
- ไม่ครบ หรือยังไม่ตรง → เปลี่ยน `รอรีวิว:` เป็น `ส่งกลับ:` บนบรรทัดเดิม เอเจนต์เห็นคำนั้นแล้วทำต่อ
- ไม่เอา → เปลี่ยนบรรทัดเป็น `- [x]` ต่อท้าย `ปิด:` พร้อมเหตุ แล้วปิดของที่เปิดไว้ถ้าปิดได้

ห้ามติ๊ก `merge:` เพราะคำอธิบายดูเรียบ ทั้งที่หลักฐานไม่มีหรือ diff ไม่ตรง card
