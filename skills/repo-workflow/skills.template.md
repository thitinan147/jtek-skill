# Skills ของลูป

วิธีเดินขั้นอยู่ที่ [workflow.md](workflow.md) ไฟล์นี้บอกว่าเปิด skill เมื่อไร

คนเขียน card และ review ของที่เปิดให้ดู skill ไม่แทนสองจุดนั้น
เปิดได้สี่จุดด้านล่าง ไม่เกินสองใบต่อจุด
ตอนหยิบ card ตอนเขียน `ถาม:` และตอนคนรับหรือปิด ไม่เปิด

จับคู่จาก `description` ของใบที่ repo นี้มีอยู่แล้ว ไม่ใส่ชื่อใบจากเครื่องอื่น
ไม่มีใบที่คำตรง ให้เดินตาม workflow แล้วเขียนใน plan ว่าไม่เจอ
ตอนหยิบข้อห้ามติดตั้ง skill

การหาหรือติดตั้ง skill อยู่นอกลูป

---

## 1. คนเขียน card

เปิดครั้งเดียวเมื่อ card ยังมีสองทางที่ผลไม่เท่ากัน นอกนั้นไม่เปิด

| เปิดเมื่อ | คำใน description |
|---|---|
| ยังมีสองทาง | grill, interview |

---

## 2. ลงมือบน branch

เทสแดงแล้วเขียวอยู่ที่ workflow ไม่เปิดใบ TDD ซ้ำ

| ลำดับ | เปิดเมื่อ | คำใน description |
|---|---|---|
| 1 | โค้ดผลิต | YAGNI, stdlib |
| 2 | เลือกใบเดียวตามลำดับนี้: บั๊กที่สาเหตุยังไม่ชัดก่อนเขียนเทส แล้วจึงการพิสูจน์บนจอหรือข้าม API แล้วจึงไฟล์ที่ตรง `<STACK_LOCK>` | diagnose, debug · browser หรือ end-to-end ใบเดียว · คำใน `<STACK_LOCK>` |

เปิดได้สองใบ ใบแรกเมื่อมีโค้ดผลิต ใบที่สองเลือกจากลำดับที่ 2 ได้ใบเดียว งานที่ไม่ใช่โค้ดผลิตเปิดได้ใบเดียวจากลำดับที่ 2

---

## 3. หลัง commit ของ `feat` หรือ `fix`

เปิดหลัง commit บน branch แล้ว เพราะรีวิวนี้เห็นเฉพาะ diff ที่ commit แล้ว
ชนิดอื่นไม่เปิดคู่รีวิว ส่งให้คนดูได้เลย รวม `docs` `style` `refactor` `perf` `test` `build` `ci` `chore` `revert`

| คำใน description |
|---|
| standards, spec |
| over-engineering, delete, stdlib |

diff แตะ auth สิทธิ์ หรือ secret ให้ใช้คำว่า security แทนแถวที่สอง
รีวิวผ่านแต่หลักฐานไม่ครบ ห้ามเปิดของให้ review

---

## 4. คน review

ไม่เปิด skill คนเทียบ diff กับหัว **ตรวจผ่านเมื่อ** และหลักฐาน แล้วเปลี่ยนคำบนบรรทัด backlog
