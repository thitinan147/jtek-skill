# tek-do-card

ทำใน repo ที่เปิดอยู่เท่านั้น ห้ามติ๊ก `merge:` หรือ `ปิด:` ห้าม merge หรือ push สาขาหลัก ห้ามหยิบข้อถัดไปหลังหยุด เปิดใบอื่นตาม `references/skills.md` ของ skill `tek-skill` เท่านั้น รูปแบบ commit ดูหัว **มาตรฐาน commit** ใน `references/loop.md` ของ skill นั้น

## เจตนาต้องปิดก่อนลงมือ

card มีชนิดเดียว ทางเดียว และหัว **ทำ** **ไม่ทำ** **ตรวจผ่านเมื่อ** อ่านแล้วลงมือได้

ยังไม่ปิดเมื่อขอบเขตคลุมเครือ มีสองทางที่ผลไม่เท่ากัน จะลบของที่อาจยังมีคนใช้โดย card ยังไม่เลือก หรือจะเปลี่ยนสัญญาที่คนอื่นเรียกโดย card ยังไม่เลือก กรณีนี้เขียน `ถาม:` แล้วหยุด ห้ามลงมือ

`<TEST_CMD>` ว่าง และ card เป็น `feat` หรือ `fix` แต่หัว **ตรวจผ่านเมื่อ** ไม่มีคำสั่งเทส ให้เขียน `ถาม:` ขอคำสั่งเทส ห้ามเปิดของให้ review

`<BROWSER_TOOL>` ว่าง และ card เป็น `fix` ที่ผู้ใช้เห็นจอ แต่หัว **ตรวจผ่านเมื่อ** ไม่มีวิธีตรวจพื้นผิว ให้เขียน `ถาม:` ขอวิธีตรวจ ห้ามเปิดของให้ review

## งานที่ย้อนกลับไม่ได้

เขียน `ถาม:` แล้วหยุด ห้ามลงมือต่อ เมื่อจะลบข้อมูล production, force-push, ส่งของออกนอก repo, หรือ merge สาขาหลัก push branch ของข้อเพื่อเปิดของให้ review ทำได้

## เกณฑ์ 3 รอบ

หนึ่งรอบคือพยายามทั้งชุดจนจบครั้งหนึ่ง หลักฐานคือเทสที่เกี่ยวข้องเขียว และถ้าเป็น `fix` ที่ผู้ใช้เห็นจอ ขั้นตอนเดิมบนพื้นผิวเดิมไม่เกิดบั๊ก

เริ่มที่ `รอบหลักฐาน` = 1 พยายามทั้งชุดแล้วยังไม่ผ่าน ถ้าค่าน้อยกว่า 3 ให้บวก 1 แล้วพยายามใหม่ ถ้าค่าเป็น 3 อยู่แล้วและยังไม่ผ่าน ให้เขียน `ถาม:` แล้วหยุด ห้ามเปิดของให้ review เทสแดงที่ตั้งใจก่อนลงมือไม่นับเป็นรอบที่ล้ม นับจากช่องใน plan เท่านั้น

## ห้ามเปิดของให้ review เมื่อ

เทสที่เกี่ยวข้องยังแดง diff ออกนอกหัว **ทำ** หรือล้ำหัว **ไม่ทำ** ตาราง **การตัดสินใจ** ว่าง หรือเป็น `fix` ที่ผู้ใช้เห็นจอแต่พื้นผิวยังเป็นบั๊ก เทสเขียวอย่างเดียวไม่พอ

## หยิบ

1. เปิด `card-loop/board.md` ตารางคำสั่งเทสยังว่างให้หยุด
2. ใช้เงื่อนไขแรกที่ตรง
   - บรรทัด `- [ ]` เป็น `ส่งกลับ:` และ `สถานะรอบ` ใน plan ยังไม่ใช่ `ส่งกลับ` → ตั้ง `รอบหลักฐาน` เป็น 1 ตั้ง `สถานะรอบ` เป็น `ส่งกลับ` commit ที่ `card-loop/` แล้วทำข้อนี้ต่อ
   - บรรทัด `- [ ]` เป็น `ส่งกลับ:` และ `สถานะรอบ` เป็น `ส่งกลับ` อยู่แล้ว → ทำต่อโดยไม่รีเซ็ตรอบ
   - บรรทัด `- [ ]` เป็น `รอรีวิว:` → หยุด คนเรียก `/tek-open-review` เอง
3. ทุกบรรทัด `- [ ]` ที่มี `ถาม:` ให้อ่าน card
   - หัว **ถาม** ว่าง และเจตนาปิดแล้ว → ลบ `ถาม:` ออกจากบรรทัด commit ที่ `card-loop/`
   - หัว **ถาม** ยังมีคำถาม → หยุด
4. ขั้นก่อนหน้าสั่งให้หยุดหรือทำต่อข้อเดิมแล้ว จบการหยิบ
5. นอกนั้นหยิบข้อ `- [ ]` ที่ไม่มี `ถาม:` `รอรีวิว:` หรือ `ส่งกลับ:` และมีไฟล์ `card-loop/backlog/<id>.md` ตามลำดับ **ทำก่อน** แล้ว **งานหลัก** แล้ว **เก็บเล็ก** ไม่มีไฟล์ card ให้ข้ามบรรทัดนั้น ห้ามเขียน card ให้ บรรทัดหัวของข้อย่อยไม่ถูกหยิบ เมื่อข้อย่อยครบให้เขียนว่าครบที่บรรทัดหัว ไม่มีบรรทัดที่หยิบได้ให้หยุด
6. ของที่ card ขอไม่มีในโค้ดแล้ว หรือเจตนายังไม่ปิดตามหัว **เจตนาต้องปิดก่อนลงมือ** → เขียน `ถาม:` ที่ card และบรรทัด commit ที่ `card-loop/` แล้วหยุด ก่อนเขียน `ถาม:` เพราะยังมีสองทาง ให้เปิดหนึ่งชื่อจาก `<TEK_SKILLS>` ที่ description พูดถึง grill หรือ interview ถ้ามี
7. เจตนาปิดแล้ว → ไปลงมือ ห้ามข้ามหัวนั้น

## ลงมือ

branch แยกจากสาขาหลัก plan อยู่ที่ `card-loop/plan/<id>.md` จาก `assets/plan.template.md` ของ skill `tek-skill`

- `fix` ที่สาเหตุยังไม่ชัด ก่อนเขียนเทสแดง ให้เปิดหนึ่งชื่อจาก `<TEK_SKILLS>` ที่ description พูดถึง diagnose หรือ debug ถ้ามี
- กำลังแก้โค้ดผลิต ให้เปิดหนึ่งชื่อจาก `<TEK_SKILLS>` ที่ description พูดถึง YAGNI, stdlib หรือ delete ถ้ามี
- `feat` / `fix` เขียนเทสของพฤติกรรมนั้นให้แดงเพราะ assertion ยังไม่จริง แล้วทำให้เขียว
- `test` เทสที่เพิ่มเขียว โดยไม่เปลี่ยนพฤติกรรมผลิตเพื่อให้ผ่าน
- `fix` ที่ผู้ใช้เห็นจอ บันทึกขั้นตอนที่ทำให้บั๊กเกิด แล้วขั้นตอนเดิมหลังแก้ต้องไม่เกิด
- ไฟล์นอก **ไฟล์ที่แตะได้** ใน plan ห้ามแก้
- งานที่ย้อนกลับไม่ได้ → ทำตามหัว **งานที่ย้อนกลับไม่ได้** แล้วหยุด
- หลักฐานไม่ผ่านทั้งชุด → ทำตามหัว **เกณฑ์ 3 รอบ** ครบ 3 แล้วให้เขียน `ถาม:` ห้ามเปิดของให้ review
- ทุกครั้งที่เลือกทาง หยุดเพื่อ `ถาม:` หรือผ่านหลักฐาน ให้เติมหนึ่งแถวในตาราง **การตัดสินใจ** ของ plan

ก่อนเปิดของให้ review รันคำสั่งจากตารางบน board

- `<TEST_CMD>` ในขอบเขตไฟล์ที่เปลี่ยน ว่างได้เฉพาะชนิดที่ไม่ใช่ `feat` หรือ `fix`
- `<TYPECHECK_CMD>` ถ้าแตะไฟล์ที่ type ครอบ และช่องนี้ไม่ว่าง
- `<LINT_CMD>` เช่นกัน
- แตะ UI และ `<BROWSER_TOOL>` ไม่ว่าง ให้ไล่เส้นที่เปลี่ยน รวมหน้าอื่นที่อ่าน state เดียวกัน
- `<BROWSER_TOOL>` ว่าง และไม่ใช่ `fix` ที่ผู้ใช้เห็นจอ ให้เขียนในของที่เปิดให้ review ว่าตรวจพื้นผิวอะไรไม่ได้

## เปิดของให้ review

ตรวจหัว **ห้ามเปิดของให้ review เมื่อ** ก่อน เข้าเงื่อนไขนั้นให้หยุดโดยไม่ตั้ง `รอรีวิว:`

หลัง commit ของ `feat` หรือ `fix` และก่อนตั้ง `รอรีวิว:` เปิดทุกชื่อใน `<REPO_SKILLS>` แถวว่างคือไม่เปิดใบอื่น ชื่อที่ไม่มีในเครื่องให้จดใน plan แล้วเดินต่อ รีวิวของใบนั้นผ่านแต่หลักฐานในหัวนั้นไม่ครบ ห้ามเปิดของให้ review

เปิดของในแบบที่ repo นี้ใช้อยู่แล้ว ถ้า repo ใช้ PR ให้เปิดใบเดิมของข้อนั้น ห้ามเปิดใบใหม่ เนื้อที่คนดูต้องมี diff ที่อยู่ในหัว **ทำ** และไม่ล้ำหัว **ไม่ทำ** ผลคำสั่งที่รัน และขั้นตอนบนพื้นผิวถ้าเป็น `fix` ที่ผู้ใช้เห็นจอ

commit งานของข้อก่อน ตรวจหัว **ตรวจผ่านเมื่อ** กับ commit นั้น ไม่นับบรรทัด `รอรีวิว:` ที่จะตามมา

แล้วแก้ board ข้อยังเป็น `- [ ]` ต่อท้าย `รอรีวิว:` พร้อมที่อยู่ของของที่เปิดให้ดู ตั้ง `สถานะรอบ` ใน plan เป็น `รอรีวิว` ห้ามเปลี่ยนเป็น `- [x]`

commit บรรทัด board กับ plan ที่ `card-loop/` คนละ commit จากงานของข้อ แล้วหยุด

เสร็จเมื่อบรรทัดเป็น `รอรีวิว:` หรือมี `ถาม:` หรือไม่มีข้อ `- [ ]` ที่หยิบได้
