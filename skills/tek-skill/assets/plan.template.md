## หลักฐานก่อนเปิดของให้ review

- ไฟล์เทส: `<TEST_FILE>`

- `fix` ที่ผู้ใช้เห็นจอ: ขั้นตอนที่ทำให้บั๊กเกิด / ขั้นตอนเดิมหลังแก้

## เปิดของให้ review เมื่อ

- ผลคำสั่งในหัว **พิสูจน์** ของ card
- `<TEST_CMD>` ของ repo นี้ ขอบเขตที่เกี่ยวกับไฟล์ที่เปลี่ยน (`feat` / `fix` ห้ามข้าม ถ้าตารางว่างใช้คำสั่งในหัว **ตรวจผ่านเมื่อ** ชนิดอื่นข้ามได้แล้วเขียนว่าไม่มีชุดเทส)
- `<TYPECHECK_CMD>` / `<LINT_CMD>` ถ้าช่องไม่ว่างและแตะไฟล์ที่ครอบ
- เนื้อที่คนดูมี diff, ผลเทส, และหลักฐานบนพื้นผิวถ้าเป็น `fix` ที่ผู้ใช้เห็นจอ ถ้า repo ใช้ PR เนื้อนี้อยู่ใน PR ใบเดิมของข้อนั้น
